# Code Edition 双盘关系运行规范

合婚不是生肖配对，也不是把两人的单盘总分平均。引擎先独立计算 A/B，再将两盘节点放入同一关系系统，
识别真正跨盘形成的互动。

## 进入条件

- 两组命局且用户明确要求合婚、互补、相处、婚期、分合或一方影响另一方：运行 compatibility。
- 两组命局只要求分别分析：运行两次 single。
- 两组命局只点名一人：只运行该人的 single。
- 一组命局问个人婚恋：运行 single，不生成关系专用分。

正式 CFS/R-AFS 需要双方完整四柱与 `male`/`female` 性别。缺少性别或时柱时仍可输出跨盘机械事实，
但 `formal_scoring=false`，不得在代码外补 MPS/CFS。

## C_R 静态关系

代码完成：

1. A/B 各自 R 层与 IMS 基础。
2. 跨盘天干、地支、三合/半合/三会、刑冲害破与墓库引动。
3. 对方能量对自己的 DFP 是否有益，以及提供者能否持续提供。
4. 夫妻宫、伴侣星、调候、路线、合类互动与波动成本。
5. BCS、RFS、MPS、CRS、CHS fit、HOI quality、RVP_static 与 CFS。

关系互动只生成一个对称事实；A/B 对换后 CFS 必须相同。若某半合/三合在一方原局已经独立成立，不把它
伪装成跨盘新结构。

## C_D 双方大运

双方大运必须同时输入。引擎重建包含 A_R、B_R、A_D、B_D 的关系系统，输出 DCS 与同步度。不能把
某一方的大运局部观察当成正式 DCS，也不能用 CFS 加减得到 DCS。

解释时区分：基础关系不差但阶段错频、基础较弱但阶段暂时支持、双方目标同频、双方压力同时攻击关系
路线。阶段性结论不能倒推为“天生合/不合”。

## C_Y 关系流年

加入一个共享流年 Y，完整重建关系系统。代码输出 YCS、R-SCS、RVP_dynamic、R-AFS、RAI。

- CFS 只扣静态 RVP。
- R-AFS 只扣含 D/Y 新节点的动态 RVP。
- RAI 只看激活强度，不进入 R-AFS。
- YCS 高且 RAI 高：结构支持推进且事件容易被触发。
- YCS 低且 RAI 高：大动但风险高，不能因“动婚姻宫”直接判结婚。
- YCS 高且 RAI 低：适合稳定经营，但未必发生大事。
- YCS 低且 RAI 低：低温、拖延或疏离倾向更强。

## 报告重点

按顺序报告：

1. 一句话关系主型，如“互补明显但高波动”或“现实合作强、情绪路线弱”。
2. IMS-A/B 与双方各自短板。
3. CFS 及 RFS、MPS、CRS、CHS、HOI、静态 RVP 的证据。
4. 若有 D，报告 DCS 与阶段同频。
5. 若有 Y，报告 YCS、R-AFS 与 RAI 四象限。
6. 将结构落到沟通规则、共同财务、家庭介入、边界、居住迁移与共同目标。

不要只说“合”或“不合”，也不要把高吸引、高事件强度等同长期稳定。
